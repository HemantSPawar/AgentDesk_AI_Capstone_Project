Please 
do not skip this part. Many beginners fail in AI projects not because the agent logic is difficult, but because the setup is messy. API keys are in the wrong place, packages are missing, project folders are confusing, or files are not organized properly.
<break time="1.5s" />
So our goal 
in this part is simple: create a clean setup, understand the project folders, prepare the environment file safely, and make sure our terminal is ready before we write the main agent logic.
<break time="1.5s" />
Before
 we run anything, let me explain the project mindset. We are not building a random script. We are building a mini product.
<break time="1.0s" />
That means our code should be organized. The knowledge base should be separate from the agent logic. The tools should be separate from the user interface. The MCP server should be separate from the main application. The configuration should be separate from the code.
<break time="1.5s" />
This separation is 
very important in real-world agentic AI systems. If everything is written inside one giant Python file, the project may work for a demo, but it becomes difficult to maintain, test, and explain.
<break time="1.0s" />
AgentDesk AI will be
 simple, but it will follow the same design thinking used in real production systems: clean folders, reusable tools, clear prompts, real RAG, real MCP, and safe configuration.
<break time="1.5s" />
Now let us open the project folder in VS Code. The project is organized chapter by chapter, so each lesson has its own folder. But setup will happen only once at the root of the project.
<break time="1.0s" />
This is important. We do not want students creating a virtual environment and environment file again and again inside every chapter. One root virtual environment and one root environment file will serve the entire course.
<break time="1.5s" />
In Chapter 2, we use a setup script to make this easier. The script checks Python, creates the virtual environment, installs dependencies, creates the environment file, and then tells us the next command to run.
<break time="1.0s" />
If Python is not installed, the script uses winget to install Python on Windows. After Python is installed, we close and reopen the terminal, then run the script again.
<break time="1.0s" />
This keeps setup simple for students. Instead of remembering many commands, they can run one setup script from the project root.
<break time="1.5s" />
The virtual environment is important because it keeps this project's Python packages separate from other projects on the system. When we build AI projects, package versions matter. A virtual environment prevents one project from breaking another project.
<break time="1.0s" />
After the virtual environment is created, the script upgrades pip and installs the packages from the root requirements file.
<break time="1.0s" />
For this project, we need packages for environment variables, OpenAI API communication, embeddings-based RAG, MCP server support, and structured validation.
<break time="1.5s" />
The student should not guess which packages are required. The project should tell them clearly, and the setup script should install everything in one attempt.
<break time="1.5s" />
Now let us talk about the environment file. This is one of the most important files in any AI project.
<break time="1.0s" />
The environment file stores secret configuration like API keys and feature flags. We do not hardcode API keys directly inside Python files.
<break time="1.0s" />
Hardcoding secrets is a bad practice because you may accidentally upload the key to GitHub or share it with someone.
<break time="1.0s" />
Instead, we keep a safe sample file called dot env example at the root of the project. This file shows what keys are required, but it does not contain real secrets.
<break time="1.0s" />
The setup script copies this sample file and creates a real dot env file. Then we add our real OpenAI API key privately.
<break time="1.5s" />
Real API keys should stay private. They should never be hardcoded in Python files or committed to GitHub.
<break time="1.5s" />
Inside the environment file, we have three important settings.
<break time="1.0s" />
The model setting controls the OpenAI model used for agent response generation.
<break time="1.0s" />
The embedding model setting controls the OpenAI embeddings model used for semantic RAG retrieval.
<break time="1.0s" />
The USE_MCP flag controls whether we are using local tool calls or the MCP server path.
<break time="1.5s" />
At the start of the course, USE_MCP stays false because we first want to understand the agent flow clearly. Later, when we reach the MCP section, we will switch to the real MCP tool server and show how tools can be exposed through a standard interface.
<break time="1.5s" />
