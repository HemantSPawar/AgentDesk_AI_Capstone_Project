Section 3: File-by-File Explanation

First, app.py

The runtime starts from app.py.
Inside app.py, the main function prints a chapter banner and prompts for customer messages in a loop.
For every message entered by the user, main calls one function: build_agent_response(message).
That function returns structured JSON, and app.py prints it to the console.
If the user types exit or quit, the loop stops.

So app.py is our interaction layer.
It does not contain business logic.
It only handles input, output, and loop control.

Second, agentdesk_ai/agent.py

Inside agent.py, the key function is build_agent_response(customer_message).
This function coordinates the entire deterministic pipeline.

Step 1 inside this function: call detect_intent(customer_message).
Step 2: call score_lead(customer_message).
Step 3: call decide_escalation(customer_message).

After getting outputs from these three functions, build_agent_response creates a payload dictionary with fixed fields:
- intent
- lead_score
- customer_reply
- internal_summary
- should_escalate
- escalation_reason
- next_action

Then this payload is converted into formatted JSON using json.dumps with indentation.

So agent.py is not deciding rules itself.
It is collecting rule outcomes from tools.py and packaging them into a standard response format.

Third, agentdesk_ai/tools.py

This file contains deterministic business logic.

Function 1: detect_intent(customer_message)

This function converts input text to lowercase so matching is case-insensitive.
Then it evaluates keyword groups in sequence.

Group 1 checks pricing intent words such as price, pricing, and cost.
If any of these appear, intent is set to pricing_inquiry.

If pricing is not matched, Group 2 checks support issue words like paid, refund, not activated, or frustrating.
If matched, intent becomes support_issue.

If that also does not match, Group 3 checks product-fit intent words like demo, integrate, integration, or whatsapp.
If matched, intent becomes product_fit_inquiry.

If no group matches, the default intent is general_question.

Important teaching point: this function uses ordered if checks.
That means first matching condition wins.
Order matters in deterministic logic.

Function 2: score_lead(customer_message)

This function also lowercases the text.
It starts with a base score of 3.

Then it adds 3 points if high commercial intent words are present, for example pricing, demo, buy, business.
Then it adds 2 points for enterprise or integration indicators such as enterprise, crm, integration.
Finally, it caps the score at 10 using min(score, 10).

So lead scoring logic in this chapter is additive and rule-based:
- Base confidence from any inquiry
- Additional points for buying intent
- Additional points for enterprise readiness

This creates a quick deterministic qualification score for sales workflows.

Function 3: decide_escalation(customer_message)

This function identifies sensitive or risk-related language.
It uses escalation keywords including paid, refund, legal, frustrating, angry, and cancel.

If any keyword appears, it returns True.
Otherwise, it returns False.

This supports safe operations by flagging messages that may require human intervention.

Section 5: Why Chapter 3 Matters

In production-grade agent systems, we need predictable control points:
- intent routing
- priority scoring
- escalation policy

If these are deterministic, teams can test and trust behavior.
Later, LLM or RAG can improve response quality, but this control layer remains stable.

This chapter also introduces clean separation of responsibilities:
- app.py handles interaction
- agent.py orchestrates
- tools.py contains business rules

This separation improves readability, maintainability, and testability.

Section 6: Student Checkpoints

Students should verify:
1. Intent changes based on keywords.
2. Lead score increases for buying and enterprise signals.
3. Escalation flips to true for sensitive support language.
4. Output JSON shape remains consistent for every message.

Common mistakes:
- Expecting open-ended LLM-style natural responses.
- Changing keyword rules without retesting sample messages.
- Ignoring condition order in detect_intent.
- Forgetting deterministic systems depend on careful vocabulary design.
